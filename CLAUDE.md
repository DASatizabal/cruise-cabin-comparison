## Project Overview

A decision guide that helps the family choose between three Norwegian Cruise Line options from Miami in June 2027:
1. 3 nights: Norwegian Getaway, Jun 11 to Jun 14 (Great Stirrup Cay, Nassau). NCL packageId 24223992 on 2026-10-15 (looked up on every run, never typed in).
2. 5 nights: Norwegian Aura, Jun 14 to Jun 19 (Puerto Plata, Great Stirrup Cay, 2 sea days). NCL packageId 25729291 on 2026-10-15 (looked up on every run, never typed in).
3. 8 nights: both back to back, changing ships in Miami on Jun 14.

The page is `index.html` (HTML, CSS and JavaScript in one file). It reads `data/prices.json` and, when present, `data/counts.json`, `data/florida.json` and `data/offers.json`. A family splash page that sells the trip and links to it is `splash/index.html` (5.3.0, section "Splash page" below). Background, decisions and probe findings are in `NOTES.md`; read it before changing pricing logic.

## Data (`data/prices.json`, schema 4)

Written by `tools/fetch_prices.py` from NCL's vacation-builder API, plain POST requests with no cookies, 2 seconds apart:
- NCL's ids, per ship, every run: the cruise page `https://www.ncl.com/cruises/<start page>` (GET, header `Accept: */*`, tried once, `data-pricing-sailings`) gives the itinerary code and packageId of the sailing on our date; `https://www.ncl.com/api/vacation-builder/itinerary/<itineraryCode>?packageId=<packageId>` (GET) must confirm the packageId, date, ship code and length and gives the sailingId. If the cruise page can't be used, the previous run's ids are tried with a warning (`warnings`), and the itinerary call still has to confirm them. Stored in `sailings[].ncl_ids` (`itinerary_code`, `package_id`, `sailing_id`, `ship_code`, `destination_codes`, `duration`, `sail_start`, `found_on`, `checked_at`). The run prints them as notices on the GitHub run's summary page.
- `https://www.ncl.com/api/cruises/v1/route-events/<packageId>` (GET): day by day itinerary; also confirms the departure date.
- `https://www.ncl.com/api/vacation-builder/v2/stateroom-types-availability`, body `{"sailingFilters":[{"packageId":"24223992","numberOfGuests":2,"filterId":"0"}]}`: one call per ship per party size 2 to 5.
- `https://www.ncl.com/api/vacation-builder/price-summary`: one call per ship per party size, for the cheapest available category, to read the tax line and the Free at Sea gratuity lines. `fareCodes` must be the default Free at Sea promotion for that cabin type (ALL4CHO for Inside to Club Balcony Suite, CHOALL4M for Suite and Haven), read from the availability answer's `offerGroups`. With BESTFARE the summary leaves out Free at Sea.
- One more price summary per ship (the age test): guests 1 adult (`reservationOwner` true), a 15 year old and a 7 year old, sent as `{"birthDate":"YYYY-MM-DD","reservationOwner":...}` with no names, for the cheapest category at 3 guests.
- NCL pages (GET, daily): `https://www.ncl.com/cruise-deals/promotion-terms` (Free at Sea Plus adult and child rates, Open Bar per day rates, soda rate) and `https://www.ncl.com/faq/what-is-ncl-onboard-service-charge` (service charge rates, minimum age 3). Stored in `rates` with `source` and `checked_at`; carried forward with a warning if a page can't be read (`--previous data/prices.json`).
- Each ship and party size (2 to 5) succeeds or fails on its own: availability, the price summary for the cheapest available category, and the formula check (cabin_total plus that summary's own gratuity lines equals its total). A failed party size keeps the previous file's prices for that ship and size (`party_sizes[g]`: `updated` false, `as_of` the time they are from, `why`); the page shows "Not updated today". The run fails if every party size on a ship fails, if there is nothing to keep, or if kept prices would be more than 3 days old. A failed age test keeps the previous gratuities under the same 3 day limit.
- 26 NCL calls per run in `fetch_prices.py` (2 cruise pages, 2 itinerary, 2 route-events, 8 availability, 8 price summaries, 2 age tests, 2 NCL terms pages), about 1 to 2 minutes. An availability answer with nothing available at a real price, or a price summary with a $0 total, is retried after 30, 60 and 120 seconds. POST requests never follow redirects; redirects, 5xx and network errors are retried after 30, 60 and 120 seconds.

Prices never depend on cabin counts. Counts live in their own file (below).

## DoubleUp watch (`data/offers.json`, schema 1, 5.2.0)

Written daily by `tools/fetch_offers.py` in the `refresh` job, before the prices: 1 NCL page load (GET `https://www.ncl.com/cruise-deals/cruisenext` through `fetch_prices.request(page=True)`, address guard, tried once), so the price job makes 27 NCL calls a day. Checked by `tools/check_offers.py` (public NCL text, dates and codes only; also in the release check when present), committed with the prices, published by "Deploy site". NOTES.md, "DoubleUp watch".
- Reads the heading with "DoubleUp" and the offer paragraph right after it (never a footnote, never more than 4,000 characters on); the page must carry NCL's CruiseNext credit terms. From the text: `types` (NCL broad types, "Balcony and above" means BALCONY, MINISUITE, SUITE, HAVEN; "any" means all) and `min_days` or `min_months`. Wording it can't read is null with a warning and never guessed.
- File: `saved_at`, `checked_on` (Eastern), `source`, `read_ok`, `warnings`, `doubleup` (`listed`, `title`, `text`, `types`, `min_days`, `min_months`, `read_on`, `since`), `last_change` (`kind` started, appeared, ended or changed, `on`, `old_listed`, `old_text`, `new_listed`, `new_text`, `marker`, `reported`). A page that can't be read keeps the previous state with `read_ok` false and a warning, never fails the price run and never opens an issue.
- Issues (main only, the refresh job has `issues: write`): one per change of the listed state or exact text, plus "DoubleUp watch started" on the first run. Marker: hash of the old state, the new state and the date the old state began; the workflow searches all issues for it before opening one, then runs `fetch_offers.py --mark-reported`. A failed search or issue only warns; the next run tries again. The issue mentions @DASatizabal so GitHub notifies the owner.

## Counts (`data/counts.json`, schema 1)

Written by `tools/fetch_counts.py` (it reuses `fetch_prices.py`'s request function and guards), checked by `tools/check_counts.py`, never by the price checks:
- `https://www.ncl.com/api/vacation-builder/itinerary/<itineraryCode>?packageId=<packageId>` (GET): sailingId, shipCode, destination codes, duration and departure date for the cabin call.
- `https://www.ncl.com/api/vacation-builder/cabin/availability` (POST, `stateroomSearchFilter`), 3 seconds apart. Full sweep: every available non-Guarantee category at every party size, most expensive first (about 140 calls). Light day: only counts under 15 plus the next pricier category each needs (about 75 calls). `auto` mode: full when the last full sweep was 3 or more Eastern calendar days ago or there is no usable previous file. The run stops if an answer mentions "hold" or "heldUntil".
- File: `saved_at`, `mode` (full or light), `mode_reason`, `last_full_sweep`, `prices_saved_at`, `pause_seconds`, `calls`, `rechecked`, `unreliable` (with reasons), and `sailings[<sailing id>][<code>]`: `open_decks`, `open_locations` (from the 2-guest call), `by_guests["2".."5"]`: `cabins_left` (null when unreliable), `reliable`, `why`, `checked_at`. Guarantee cabins have no entry.
- Count rules: location totals of a category's call minus those of the next pricier category's call; unreliable when the call returns another broad type's code (location lowestPriceCategory or a listed cabin), when prices tie, or when the subtraction is not positive.

File layout:
- `saved_at` (UTC), `guest_counts` [2, 3, 4, 5], `rates` (`free_at_sea_plus`: `adult_per_day`, `child_per_day`; `open_bar`: `per_day_2_to_5_nights`, `per_day_6_plus_nights`, `soda_per_day`; `service_charge`: `suite_haven_per_night`, `standard_per_night`, `min_age`, `suite_haven_types`; each with `source` and `checked_at`), `rate_warnings`, `checks` (`rates`: price summary gratuities against the terms rates x nights, logged only; `formula`: one entry per ship per party size, all must be `ok`; `ages`: one entry per ship for 1 adult + 15 + 7, must be `ok`; `extra_guest_mismatches`: logged only).
- `warnings` (text list; a fallback to the previous run's ids, null taxes, null gratuities, a null deposit and a null final payment date must each have one, starting with the ship's name; a null Suite and Haven rule one starting "Deposits:"). `taxes_per_guest`, `gratuities` and each entry of `rates` may be null, only with a warning (`rate_warnings` for rates).
- Payment (schema 4, 5.2.0, no extra NCL calls; NOTES.md, "Payment data"): each `price_summaries` entry has `deposit`, `deposit_due_hours` and `final_payment_due` from NCL's `paymentOptions` (DEPOSIT and FULL; the HOLD payment option is never used). Per ship `payment`: `source`, `final_payment_due`, `standard_deposit_per_guest` and `standard_deposit_checked_at` (Inside to Club Balcony Suite), `by_guests["2".."5"]` (`deposit`, `deposit_type`, `deposit_category`, `due_hours`, `as_of`, `why`), `deposit_offer` (NCL's words from the availability answers, or null). Top level `deposit_rules` (`percent_of_fare` 10 for SUITE and HAVEN, NCL's rule, `confirmed_on`, `confirmed_by`, `source`) and `checks.deposits` (a failed check never stops the run; the number it checks is null with a warning). The release check accepts the committed schema 3 file until the first refresh on main.
- `sailings[]`: `id`, `ship`, `ship_short`, `itinerary_code`, `package_id`, `ncl_ids`, `kids_sail_free` (NCL's offer from the availability answers: `title`, `short`, `description`, `codes`, `types`, `checked_at`; null when not listed), `depart`, `return`, `nights`, `url`, `party_sizes` ("2" to "5": `updated`, `as_of`, `why`), `taxes_per_guest`, `gratuities` (`open_bar`: `title`, `per_guest` for 21 and over, `soda_under_21_position_2`, `under_21_position_3_plus` 0; `specialty_dining`: `title`, `per_guest` for 13 and over, `under_13` 0), read daily from an age test price summary, `terminal`, `ports`, `price_summaries`, `types[]`.
- Each type: NCL code (STUDIO, INSIDE, OCEANVIEW, BALCONY, MINISUITE, SUITE, HAVEN), `title`, `match`, `categories[]`.
- Each category: `code` (pricedCategoryCode, like B4), `title`, `guarantee`, `solo`, `capacity` (from the 2-guest call only, null when unknown), and `by_guests` "2" to "5": `available`, `sold_out`, and when available `price_pp` (average per person with NCL's cents, includes taxes, not gratuities), `cabin_total` (`price_pp` x guests, rounded to whole dollars; equals NCL's fare plus taxes), `added_vs_2`; when unavailable a `reason` ("Sold out", "Holds only X guests", "Sold out for this party size").
- Each category also has a plain `description` (shown instead of the code), `decks`, `location` (forward, midship, aft), `size`, `details_source` and `shares_ncl_description_with`. Rules (see NOTES.md, "Cabin descriptions"): NCL first; NCL's decks, location and size are used only when NCL's group has that one code; for the Getaway, per-code decks come from the owner's public Deck Finder repo (`ships/ncl/getaway/geometry.json`, read only) and are kept only when they fall inside NCL's deck list; never guess a deck or location; Guarantee cabins list no decks. The page rebuilds the description with the same rules and fills gaps (missing decks or location) from `counts.json`'s `open_decks` and `open_locations`, only when that file is fresh.

## Pricing logic (in `index.html`)

- Free at Sea switches per cabin (per ship; 8 nights has one set per ship): Open Bar (default on), Specialty Dining (default on), Free at Sea Plus (default off). - `.github/workflows/refresh-prices.yml` jobs: `decide` (first; `tools/decide_run.py` reads the Eastern date (America/New_York) of `saved_at` in both data files on the newest `main` and compares it with today's Eastern date; `--now` sets the clock for tests. From Jun 11, 2027 (Eastern) every run, manual too, skips everything. Timed runs only (scheduled, or workflow_dispatch with input `source` = `timer`): both saved today skips `refresh`, `publish`, `counts` and `publish-counts` and the run ends as a success; prices saved today but counts not skips `refresh` and `publish` and runs only counts; otherwise everything runs.
